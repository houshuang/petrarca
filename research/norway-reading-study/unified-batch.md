# Unified Norway study batch operator

Registered in the [22 September experiment log](../experiment-log.md) before implementation. This is a bounded operator command, not a scheduled collector or phone feature. It is intended to be run after the server has the matching canonical `study_intake` and `study_readings` operator changes.

```sh
python3 scripts/reading_study_batch.py \
  --workdir PRIVATE_BATCH_DIRECTORY
```

The `--wonderings` inventory is optional. With it, the command processes those exact original-source quotes and extracts wonderings from any newly registered source. Without it, it extracts explicit wonderings from each registered source transcript and caches even zero-result extractions by source hash. A private `--discovery-snapshot` can replay a previously captured complete search for controlled tests; normal runs always query the authenticated Tana Outliner for the full journal tag in workspace `VSazTvUjtQ`. A full 100-result page is a hold, not proof of completion. The two verified 2023 template/demo IDs are reported as out of scope. All other new entries need a raw journal and audio match plus relevance evidence before registration.

Discovery and source acquisition use a narrow `codex exec --json` MCP bridge with only `search_nodes`, `read_node`, and `get_children` enabled for `tana-outliner`. The command captures raw tool results privately; it does not treat the agent's summary as the original transcript. A matching audio node needs the same journal breadcrumb and calendar date, a complete child list, and full raw audio-node markdown. The original media is downloaded to a temporary file, checked for complete transfer, atomically renamed, checksummed, and archived with raw transcript and source metadata. Signed URLs remain in private evidence and are removed from runtime transcripts. Changed originals or ambiguous/unavailable audio are held rather than silently replacing a source.

New sources receive at most twelve question candidates; the batch processes at most twenty new sources and eight pending readings per invocation. Explicit wondering extraction inventories up to forty per source, separately from that eight-reading work cap. The extractor must affirm complete coverage with no overflow; an uncertain or saturated inventory holds the source and is reported rather than quietly dropping later wonderings. The model budget is forty attempts per invocation with one worker. Source-linked authoring uses `gpt-5.6-sol`; independent review uses `gpt-6-astra`. Both go through Limbic's cached callable transport around Codex, with immutable model/schema/prompt/source/corpus cache keys. The reviewer sees current canonical items, position questions, readings, targets, sibling candidates, and original source context. Every candidate gets an explicit verdict and validated match IDs; Limbic's blind audit, coverage and demote-only helpers check the fold. Duplicate means the same retrieval aspect. Related questions with a different aspect can remain distinct. Contradictions and uncertain citations stay on hold.

Accepted questions go through the existing `study_action('intake', ...)` action, now with explicit accepted indices, full reviewer coverage and a hash of the exact draft and current content corpus. A source already published can receive a later reviewed amendment for held questions without rewriting old items. Readings are generated only from explicit original wonderings, one step deep, with initially unselected targets. Reading prose uses short plain paragraphs: known Markdown citation links are normalized before target span checks, hashing, and review, while malformed markup or URLs hold; the separate citations remain intact. Existing original quote/intent pairs, including the three pilot readings, are reported as already processed. New readings go through `readings-import` with exact quote, source and content snapshot checks; they do not create scheduling positions until the reader selects a target.

The private workdir holds a SQLite stage ledger, call cache, raw MCP and archive evidence, model packets, and per-run reports. Reuse the same workdir after interruption. A lost server response is reconciled against a canonical publication receipt or existing brief ID before any retry. Stale content snapshots force a fresh review; a source change invalidates cached authoring. Held reading targets remain visible in the durable plan and require a new reviewed brief version before they can be offered. Rejected material, caps, incomplete discovery, missing audio, model failures and unsatisfied review coverage are explicit report entries. The process exits nonzero while failures or deferred omissions remain.

The command does not grade the reader, choose quiz targets, infer reading from page checkpoints, infer unaided recall from open-book notes, or change old runs and scheduling. The three existing pilot readings have not yet been tried by the reader, so no usefulness conclusion follows from their publication.

Published sources are recognized by node identity and are not re-fetched on every run; editing an already published Tana note needs an explicit source-revision reconciliation.

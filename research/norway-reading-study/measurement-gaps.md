# Measurement gaps for independent review

Audit date: 13 September 2026. These are limitations of the deployed pilot
`c6db8f317bcf16eee3343aea658610be9a6da4a7`, assessed before any recorded study run.
Recommendations below are **proposals**, not newly activated behavior. The
[design account](experimental-design-review.md) defines the intended outcomes.
Priority means risk of losing interpretable evidence, not a demand to stop reading.

| ID / priority | Observed limitation and evidence | Consequence | Proposed remedy / recoverability |
|---|---|---|---|
| M01 / before future timed sessions | Original MP3 durations are known; no reliable reading/speaking/break boundaries. See [first batch](first-batch.md). | We cannot report exact active reading time or page-specific reading speeds. Silence does not establish reading. | Keep elapsed recording as measured; add low-burden start/end and optional interruption markers. Speech segmentation may estimate voiced time, not infer attention. Historical gaps remain unknown. |
| M02 / before time comparisons | [StudyReview](../../app/components/study/StudyReview.tsx) resets elapsed time on appearance/foreground and logs lifecycle events; [client event schema](../../app/lib/study-api.ts) has no stable visit/device/boot/encounter ID, sequence or absolute monotonic timestamp. Stats uses the generic logger. | Summing event elapsed values double-counts; app-open time is not active learning. Crashes and silent abandonment leave unbounded intervals; source-link dwell is unknown. | Add a defined foreground-time model, stable encounter IDs, monotonic timing/sequence, explicit pause/idle policy and bounded missing-end treatment. Join generic/study events deliberately. Attention remains an estimate even with complete telemetry. |
| M03 / before latency analysis | `reveal_time_ms` in [AspectCard](../../app/components/AspectCard.tsx) and [StudyCard](../../app/components/study/StudyCard.tsx) is completion time minus reveal time, using wall clock. | It is post-reveal elapsed time, not unaided retrieval latency; background time may be included. | Preserve original field; introduce correctly named/versioned interval fields. Do not silently relabel old values. |
| M04 / before repeated voice attempts | [uploadAudio](../../app/lib/study-api.ts) reads HTTP status but discards server response body. Local audio ID is logged after upload; [save_audio](../../scripts/study_engine.py) creates its own server ID. Start/stop events do not share a capture-attempt ID. | Multiple captures for the same run/item/purpose cannot always be joined one-to-one from metadata alone. | Generate attempt ID before capture; carry it through events, local file, upload, server audio and ASR. Return/store server ID and content hash. Retrospective joins must declare ambiguity. |
| M05 / before next behavior release | [run snapshot and event handler](../../scripts/study_engine.py) freeze selection content and revision, but completion executes current grading code/FSRS. App update ID is attached to events; actual server build/effective grading policy at execution is not. | An old run completed after deployment can be attributed to the wrong implementation. | Stamp execution commit, policy, schema and migration versions per operation, including offline late arrival. Preserve selection revision separately. Release times alone are weaker evidence. |
| M06 / before formal outcome collection | Current three voice prompts are practice with feedback. There are no versioned baseline/post/delayed assessment forms, scoring records or scheduled follow-ups. | Practice self-grades cannot stand in for comparable knowledge dumps or demonstrated integration. | Review and freeze a small assessment core, record book/help/feedback state, assess free recall before cues, retain raw audio and score uncertainty. Follow-up dates and reminders remain unactivated proposals. |
| M07 / irrecoverable original-baseline limit | English baseline focuses on pre-800 history and spontaneous questions. Conversation includes AI explanations before a new assessment. | Unmentioned knowledge is not absent; later historical periods have no demonstrated initial baseline. A new test is already post-exposure. | Preserve original exactly. Label next capture first post-reading observation; establish pre-volume baselines prospectively, recording prior exposures and language. |
| M08 / before accumulating unique evidence | Database backup was checked; independent backup/restore of Mac recordings/conversation archive and server audio has not been verified. [Evidence index](evidence-index.md). | A lost device/disk could remove irreplaceable observations despite versioned documentation. | Verify encrypted independent backup and sample restore, with manifest coverage and retention/deletion policy. Git documentation is not an audio backup. |
| M09 / ongoing collection | Conversation exporter is manual; only two registered sessions are included. Tana recording import is a bounded batch. No verified forum/Claude-web coverage. | New recordings, chats, decisions or external learning may never enter the index. | Maintain source registry and handoff procedure; add collection monitoring only as an explicitly specified implementation. Mark searched sources and gaps; never claim universal coverage. |
| M10 / before cross-session language scoring | Norwegian reading uses Soniox v5 plus editorial layers; mobile ASR uses existing v4 path. Neither is gold-standard Norwegian transcription. Book vocabulary hints can bias output. | Changed ASR quality can resemble changed knowledge; fluent corrections may introduce claims the participant did not make. | Preserve raw audio, ASR version/config, edits and uncertainty. Audio-check an independently sampled subset and all score-critical ambiguous phrases; never overwrite raw speech. |
| M11 / before generalizing across books | Thirteen pilot items and twelve broad target candidates are curated, not a representative syllabus sample. No outcome-depth/target merge-split registry. | Selected familiar prompts can inflate apparent coverage. Term recognition and independent explanation are different outcomes. | Define target inclusion/exclusion, intended depth and stable lineage; separate fixed evaluation targets from changing practice targets. Report denominators and selection. |
| M12 / before attributing growth to app mechanisms | Wonderings are captured but answer/external-reading encounters and subsequent explanation changes do not form a complete linked chain. | App answers, books, conversations and other learning are confounded. | Link wondering → source episode → response/version → actual encounter → later observation. Minimal optional exposure notes, not a burdensome diary. Unknown exposure stays unknown. |
| M13 / before efficacy claims | One self-selected reader, adaptive items, self-grades and repeated testing; no independent comparator or blinded outcome scoring. FSRS is a scheduling mechanism, not a validated comprehension measure. | Cannot infer causal superiority of Petrarca, universal learning rates, or unassisted long-term decay. | Descriptive longitudinal case study; blinded independent scoring of a subset, fixed core forms and phase-specific analysis. Any randomized comparison needs a separate prospective design. |
| M14 / before interpreting missing mobile events | Runtime export at 06:51:08.313 UTC has zero study runs/events/audio. Production endpoint and OTA checks passed; first real iPhone capture/adoption was not verified. | Zero rows establish no stored pilot activity at cutoff, not zero personal study or successful physical-device use. | Observe first genuine session and upload without injecting synthetic user data. Record device/build adoption and missingness explicitly. |

The highest-value next implementation is reliable session/attempt/version linkage
plus a small comparable assessment protocol. More card generation alone would not
resolve these measurement gaps. Preserve the enjoyable reading method while
reviewing measurement burden; “everything logged” is not itself an outcome model.
